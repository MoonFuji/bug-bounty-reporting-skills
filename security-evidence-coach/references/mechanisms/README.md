# Mechanism library

These chapters support human-directed assessment of designated systems. They teach
security guarantees and composition assumptions, not exploit recipes. Select by
the unresolved responsibility, not by a quota of vulnerability classes.

| Responsibility | Chapter |
|---|---|
| Who may do what to which object or fields? | [Identity and permission](identity-and-permission.md) |
| Which state and time govern a delayed action? | [State and asynchronous work](state-and-async.md) |
| What exactly does a signed statement establish? | [Signed statements](signed-statements.md) |
| Why is this artifact eligible for this deployment? | [Build and delivery](build-and-delivery.md) |
| Which guarantee belongs to the library versus its caller? | [Component contracts](component-contracts.md) |
| What effective authority and resource lifetime apply? | [Process and resource boundaries](process-and-resources.md) |
| Do layers agree on identity, lengths, and ownership? | [Representation and memory](representation-and-memory.md) |
| Which assurances cover a device update or measurement? | [Device update assurances](device-updates.md) |

All miniature examples are fictional. Stable concepts are explained directly;
version-specific library behavior must be established from the designated revision.
External reading status remains in [the source register](../sources.md).
